# Ride Work 1: Auto-finish, Height Limits, Live Meter, Train Length, Safety Limits — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the owner's ride decisions R1, R2, R5, R6, R7 and R8 of 2026-11-12 for every track ride: Auto-finish, looser height limits with an intensity step, a live speed and G meter in the builder, trains simulated with their length, and hard safety limits at build, test and open time.

**Architecture:** All rules live in `src/sim/rides/track/` and are reached through commands and pure query functions; the builder UI only reads them. One new physics primitive (the train's acceleration and G averaged over its cars) feeds the test lap, live operation, a new *section projection* (an open-track simulation from the station that the meter, the placement rule and the Auto-finish search share), and a new safety module. Auto-finish is a deterministic, bounded, time-sliced weighted A* over the ride's plain pieces whose every node is checked with the same tile rules and the same physics; one new atomic command builds the whole path. Nothing new is saved: the save schema stays 3.

**Tech Stack:** TypeScript (strict), Vite, Canvas 2D, Vitest, Playwright (projects `desktop` 1280 × 800 and `phone` Pixel 7).

**Spec:** `docs/superpowers/specs/thrills-and-chills/ride-decisions-2026-11-12.md` (owner decisions R1–R8). ## Decisions this plan makes (with reasons)

These are the answers to the open questions; every task below follows them.

1. **Intensity step (R2).** `+0.10` intensity (10 hundredths) for each whole metre the circuit climbs above the station beyond the type's *old* limit, capped at `+2.00` (200 hundredths), added after the §4.10 formula and the water extras and clamped to 10.00. Reason: integer hundredths keep the sim exact; at 0.10 / m a family ride 8 m over its old limit (Junior Coaster at 20 m) gains 0.80, which pushes it out of the calmest guests' range (`maxIntensity = 2.0 + 0.08 × T`), and the cap of 2.00 makes a very tall family ride count as a thrill ride for most guests without letting height alone dominate a coaster's rating. The old limit is kept as data (`intensityHeightM`) so the card can show it. Provisional, logged in `tuning-log.md`.
2. **Train length (R6).** A train of `n` cars is sampled at its `n` car centres (the positions `trainCarPoses` already draws). The along-track acceleration is the mean of the cars' gravity and friction terms (drag stays `c_d·v²` once, it depends only on v); mass cancels because every car has the same mass. The measured G is the mean over the cars too: vertical G is the mean of the cars' vertical G, lateral G is the absolute value of the mean signed lateral term. Reason: the owner's words ("forces are averaged over every car"); averaging keeps the rating scale the formulas were tuned for. A one-car train gives exactly today's numbers (its only car is the centre), so the Spinning Mouse, karts and boats do not change at all.
3. **What the limits are measured on.** The hard limits (R7) and the meter (R5) use the same 5-tick moving average and the same car averaging as the test lap's `posGMax`, `vertGMin`, `latMax`, compared as integer hundredths: `posG > 600`, `vertG < −200`, `lat > 300` are over the limit; exactly 6.00, −2.00 and 3.00 are allowed. Reason: one number, one rounding, everywhere: the meter can never show "ok" for a piece that the open check then refuses for the same value.
4. **The meter projects by simulation, not by a local estimate (R5).** It simulates the test train from the station dispatch over the current open track plus the candidate piece, with `stepTrain` itself. Beyond the last piece the track is assumed to run straight on at the end's pitch and bank with no curvature (a *virtual run-out*), so the whole train can cross the candidate. The *section* is the candidate piece; its values are taken while the train's centre is on it. Reason: R5 says "the same physics as the test run"; a local estimate would disagree with the test exactly where it matters (crests, valleys, long trains). Cost is held down by caching the run over the existing track (see 5).
5. **Performance budget.** The simulation over the existing track (the *prefix*) is computed once per track change and cached by the layout object (`WeakMap`, never saved); each candidate continues from the cached state. Budgets measured by `tests/bench/projection.bench.ts` on desktop: prefix ≤ 8 ms on a 300-piece track, one candidate ≤ 1 ms (phone ≈ 4×: ≤ 32 ms once per built piece, ≤ 4 ms per ghost change). The projection runs only when the ghost changes, never per frame. A deterministic unit test pins the step counts so a regression shows without timing.
6. **Where safety is checked (R7).** Three places, one module (`safety.ts`): (a) **build**: `planAppend` (the command's and the ghost's shared check) refuses a piece whose projected section is over a hard limit, after the tile and support checks and before cash; (b) **test**: `runTestLap` is unchanged in meaning (`passed` = the lap finished) and also reports the first piece where a limit was passed; (c) **open**: `canOpenTrackRide` refuses a passed test that is over a limit, naming the value and the piece. A stall blocks opening (as today) but never building: the meter warns "Train stops on piece n" and Build stays enabled, because the player may fix it with a chain lift or a lower hill. An open ride is never closed by the safety rule; it is checked again when it next opens. Brake speed and chain changes on existing pieces are not projected (they are caught by the next test).
7. **The place on the map.** The trouble place (stall piece, or the first piece over a limit) is derived on demand by re-running the deterministic test lap (`runTestLapDetailed`, cached by the stored `TestResult` object): it is shown as a danger outline on the piece's tiles while the ride is selected, the test message's tile points at it, and the ride panel gets a "Show on map" button. Reason: no new saved field.
8. **Saves and existing parks.** No field is added to `TrackRideData`, `TestResult` or `TrainState`; the schema stays 3 and no migration or load step is added. Stored test results and ratings of saved rides are kept as they are and recomputed only at the ride's next test (any track, chain, brake or train change clears the test, as today). Open rides keep running under the new physics; if a train ever stalls, the existing fault guard closes the ride with "Ride closed after a fault. Run a new test" (phase-2 §4.7). No saved ride can be over its old height limit, so no saved rating misses the intensity step. Reason: design §7 forbids partial state and invented values; recomputing at load would silently change ratings and close open rides with riders aboard. Task 9 proves on the shipped fixtures that the saved open coaster keeps running.
9. **Auto-finish search (R1, R8).** Weighted A* from the track end to the station's entry joint over the ride's *plain* pieces (pieces of its set and groups with `special === null` and not in groups `L`, `Cs`, `Hx`; each chainable piece also with a chain when the type allows chains). Priority `f = g + 2·h` with `g` = track length added (mm) and `h` = a tile-distance estimate (mm); ties by lower `h`, then by insertion order; children in piece-table order, without chain before with chain; one visit per joint. Limits: 40 pieces, 20,000 expanded nodes, 8 full-lap tries. Each child must pass the full `addTrackPiece` tile rules against the world plus its own ancestors, and its projected section must not stall or pass a hard limit; a goal must also pass the closed test lap with no limit passed (R8). The search runs in slices of 1,500 nodes per frame so the phone never freezes; it is deterministic because the order never depends on time. Reason: bounded, explainable, and safe by construction; the shortest-track path is usually also cheap.
10. **What the player sees and pays (R1).** "Auto-finish" in the piece step → "Looking for a way back to the station" → the whole path as a ghost, "Adds 9 pieces · $1,234", Confirm (with the price) and Cancel; or the reason no path was found. The price is the sum of the pieces' normal prices (no fee). Confirm sends one command `autoFinishTrack` with the pieces; the sim re-checks everything and builds all of them or none. Undo then removes pieces one at a time, as today.

## Owner change (2026-11-12, accepted with the plan)

Ratings use the average over the cars (as planned). **Safety checks use the strongest car:** the hard limits (6.0 G, −2.0 G, 3.0 G lateral), the meter's levels and the Build/Open refusals compare the largest value over all cars (the most positive and the most negative vertical G, the largest lateral G), so no seat passes a limit. Tasks 2, 3, 4, 5 and 6 return both values (`avg` for ratings, `worst` for safety) and their tests assert the worst-car rule with a long train where the rear car is stronger than the average.

## Global Constraints

- TypeScript strict; `npm run typecheck` prints no error.
- Determinism (design §5.4): the sim uses no clock, no `Math.random`, and no runtime trig outside `src/sim/trig`; physics uses `+ − × ÷` on doubles and rounds state to integers (mm, mm/s, hundredths, cents); every loop runs in a fixed order. Caches are derived, keyed by objects (`WeakMap`) and never saved.
- Saves (design §7): schema stays **3**; no field is added to `TrackRideData`, `TestResult`, `TrainState` or any saved shape; `src/save/**` is not changed.
- Module rules: `src/sim/**` imports nothing from `src/ui/**`, `src/render/**` or `src/input/**`. The command is the final word: every rule is enforced in the sim; the UI calls the same sim functions for previews.
- Values (owner): new height limits (climb above the station) Steel 75, Inverted 70, Wooden 60, Bobsled 35, Log Flume 30, Spinning Mouse 24, Junior 20, Monorail 24, Rapids 15, Mini Railway 16, Ghost Train 10, Go-Kart 6 m. Hard safety limits: vertical G above **6.0** or below **−2.0**, lateral G above **3.0**. Rating penalty limits stay **5.0 / −1.5 / 2.5**.
- Strings: every player-visible text is in `src/data/strings/`, registered for the pseudo-locale `en-XA` and, for sim reasons, for `localizeReason` exactly as `TRACK_ERR.tooHigh` is; no text ends with a period.
- UI: controls at least 44 × 44 CSS px with 8 px gaps; colours only from tokens in `src/styles/tokens.css` (canvas: the existing safe ghost constants in `src/render/track/`); a level is never shown by colour alone (an icon or a word goes with it); a frame with no change writes nothing to the DOM; the phone's condensed piece panel stays at most 240 CSS px high at 100 % text at 390 × 844 (Task 22 rule); nothing clips at 175 % text in `en-XA`.
- No test is weakened. A pinned number that changes because of R2 or R6 gets the new value and a comment naming the decision (`// R6 (owner 2026-11-12): forces averaged over 4 cars`).
- Living documents change in the same task as the code they describe.
- Gate for each task: the task's own tests, then `npm run typecheck && npx vitest run tests/unit/track`; the full gate (`npm run typecheck && npm test && npm run e2e && npm run build && node scripts/check-release.ts --no-build`) runs in Task 9 and before any merge.

```ts
export interface SectionProjection {
  /** The train's centre crossed the whole candidate piece. */
  reached: boolean;
  /** 0-based piece where the train stops (on the candidate or before it), or null. */
  stallPiece: number | null;
  stallKind: 'stop' | 'loop' | 'corkscrew' | null;
  /** Top speed and 5-tick-window G extremes while the centre is on the candidate (mm/s, hundredths); 0/100/100/0 when never reached. */
  vMaxMms: number;
  posGMax: number;
  vertGMin: number;
  latMax: number;
  breach: SafetyBreach | null;
}
export interface ProjectionSnapshot {
  train: TrainState;
  win: { gv: number; gl: number }[];
  ticks: number;
  stall: { piece: number; kind: 'stop' | 'loop' | 'corkscrew' } | null;
}
export function projectPrefix(data: TrackRideData, type: TrackTypeDef): ProjectionSnapshot;
export function continueProjection(
  pieces: readonly TrackPieceInstance[], type: TrackTypeDef, cars: number, from: ProjectionSnapshot,
): { projection: SectionProjection; next: ProjectionSnapshot };
export function projectSection(data: TrackRideData, type: TrackTypeDef, candidate: TrackPieceInstance): SectionProjection;
```

- Rules (not determined by the signatures):
  - The simulation is the test lap's: `dispatchedTestTrain`, `stepTrain` with `{ laps: Number.POSITIVE_INFINITY, holdFrontMm: null, leader: null, slowFactor: 1, cars, carLenMm }` on `buildLayout(pieces, true)`; G window and station exclusion exactly as in `runTestLap`. Monorail stops are not simulated (no dwell; speed and G are unaffected).
  - **Snapshot point:** `projectPrefix` steps until the next step could sample past the end of the existing track, i.e. stops at the last tick with `front + v·DT·1000 ≤ startMm[n]` (front = `s + trainLen/2`), so every sample it used lies on real pieces. It is cached in a `WeakMap` keyed by `getLayout(data)` (which `clearTest`/`invalidateLayout` replace on every piece, chain, brake or train change), together with `carsPerTrain`.
  - `continueProjection` clones `from`, steps on `pieces` (existing + candidate) and measures while the centre is in `[startMm[last], startMm[last + 1])`; it records `next` at the same snapshot rule against the candidate's end; it stops when the centre leaves the candidate, on a stall, or after `PROJECTION_MAX_TICKS` (then `reached = false`, `stallPiece = null`). A stall already in `from` is returned at once for any candidate.
  - `breach = safetyBreachOf({ posGMax, vertGMin, latMax })` of the section.

```ts
export interface AutoPiece { defId: string; chain: boolean }
export type AutoFinishOutcome =
  | { kind: 'found'; pieces: TrackPieceInstance[]; cost: Cents; test: TestResult }
  | { kind: 'none'; reason: string };
export interface AutoFinishSearch {
  /** Expand up to `maxNodes` nodes; the outcome when finished, else null. */
  step(maxNodes: number): AutoFinishOutcome | null;
  readonly nodes: number;
}
export function startAutoFinish(world: World, rideId: number): AutoFinishSearch;
export function findClosingPath(world: World, rideId: number): AutoFinishOutcome; // step(Infinity)
export function planPath(
  world: World, ride: Ride, data: TrackRideData, type: TrackTypeDef, pieces: readonly AutoPiece[], ctx: CommandContext,
): { ok: true; plans: PiecePlan[]; cost: Cents; test: TestResult } | { ok: false; reason: string; index: number | null };
```

- **Search algorithm** (the signatures do not determine it):

```text
start: refuse when circuitClosed, when data.pieces.length is 0, or when projectPrefix(data).stall
       (reason autoFinishStallsFirst, n = stall piece + 1)
goal  = pieceEntryJoint(data.pieces[0])                      // the station entry joint
base  = buildOccupancy(world)                                 // once per search
root  = { joint: trackEnd(...), depth 0, g 0, run: unsupported run at the end, snap: projectPrefix(data) }
open  = binary heap ordered by (f = g + weight·h, then h, then seq); seq = insertion counter
seen  = Set of joint keys "x,y,z,dir,slope,bank"
h(J)  = TILE_MM · (|J.x − goal.x| + |J.y − goal.y| + round(|J.z − goal.z| / STEEP_RISE_M)
                   + quarterTurns(J.dir, goal.dir) + (J.slope ≠ 'F' ? 1 : 0) + (J.bank ≠ 'none' ? 1 : 0))
loop while open not empty and nodes < nodeLimit:
  N = pop; if seen has N.joint: continue; add it; nodes++
  extra = Occupancy of N's ancestors' tile plans (ownsGround = takesGround)
  for def in piecesForEnd(type, N.joint.slope, N.joint.bank) filtered to plain pieces, table order:
    for chain in (def.chainable && type.chain ? [false, true] : [false]):
      piece = instance at N.joint; tiles = checkPieceTiles(..., { occ: base, extra, runBefore: N.run }); skip if not ok
      skip if data.pieces.length + N.depth + 1 > MAX_PIECES or N.depth + 1 > maxPieces
      { projection, next } = continueProjection(path pieces, type, cars, N.snap)
      skip if projection.stallPiece !== null or projection.breach
      child = { joint: exit joint, depth + 1, g + def.lengthMm, run: tiles.runAfter, snap: next, cost + pieceCost(...) }
      if exit joint equals goal:
        lapTries++; lap = runTestLapDetailed(map, closed scratch data, type)
        if lap.result.passed and !safetyBreachOf(lap.result): return found(path, cost, lap.result)
        if lapTries == AUTO_FINISH.lapTries: return none(autoFinishNone)
        continue                                   // a goal is never expanded further
      push child
return none(autoFinishNone)
```

  The scratch data is `{ ...data, pieces: [...data.pieces, ...path], circuitClosed: true }` (a new object, so no cache of the real ride is touched). `planPath` runs the same per-piece checks in order for the given list (no search), then: last exit joint equals the goal (else `autoFinishNotClosing`, index null), the closed lap passes with no breach (else `autoFinishLapFails`), then `canAfford(total)` (else `notEnoughCash`). The handler: `trackContext`, `editBlock`, `circuitAlreadyComplete`, 1 ≤ length ≤ `maxPieces`, `planPath`; then `enterBuilding` if needed and `applyPlan` for every plan in order; result `ok(cost, [TRACK_WARN.circuitComplete])`. Nothing is written before every check has passed.
